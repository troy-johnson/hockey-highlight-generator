# V3 Hockey Highlight Pipeline — Design Spec

**Date:** 2026-04-25
**Status:** Approved for implementation

---

## Goal

Replace the current export-based workflow with an end-to-end pipeline:

- **In:** raw GoPro chapter files (two cameras, one game folder)
- **Out:** a pre-cut ~10-15 min candidate reel on Track 1 ("Game") of the Resolve template project, multicam angles pre-switched, ready for manual review and trim to ~5-6 min

**Eliminates:**
- The manual Resolve stitch + export step before detection
- Scrubbing through 1+ hour of footage to find clips
- Manual camera angle switching per clip

**Does not eliminate (manual remains):**
- Reviewing the candidate reel and deleting unwanted clips
- Adding slo-mo replay for goals
- Adding graphics, titles, score bugs

---

## Current workflow (V2)

```
GoPro chapters
  → Resolve: import chapters, stitch, export cam1.mp4 + cam2.mp4
  → hockeydetect cam1.mp4 cam2.mp4
  → Resolve: import markers.fcpxml, run expand_markers.py
  → manually scrub ~1 hr, evaluate and keep/delete clips, switch angles
```

## Target workflow (V3)

```
GoPro chapters
  → hockeydetect game_folder   (new: no export needed)
  → Resolve: run compile_reel.py   (new: one-click assembly)
  → review ~10-15 min candidate reel, trim to 5-6 min, add graphics
```

## Game folder structure

```
game_folder/
  cam1/
    GOPRO1801.MP4
    GOPRO1802.MP4
    ...
  cam2/
    GOPRO1901.MP4
    GOPRO1902.MP4
    ...
  [generated by hockeydetect:]
  rois.json
  events.csv
  markers.csv
  markers.fcpxml
  markers.edl
  sync_info.json
  cam1_concat.txt
  cam2_concat.txt
```

Both `cam1/` and `cam2/` are scanned for `*.MP4` (case-insensitive), sorted by filename. Alphabetical order is always correct for GoPro chapter sequences.

File-mode (`hockeydetect cam1.mp4 cam2.mp4`) remains fully supported for backwards compatibility.

## Stage 1 — Detection (command line)

### New script: `v3/scripts/discover.py`

Scans a game folder and returns sorted chapter file lists for each camera.

```
discover(game_folder) -> {
  "cam1": ["/path/cam1/GOPRO1801.MP4", "/path/cam1/GOPRO1802.MP4", ...],
  "cam2": ["/path/cam2/GOPRO1901.MP4", ...]
}
```

Raises a clear error if `cam1/` or `cam2/` subfolders are missing or empty.

### New script: `v3/scripts/gopro_meta.py`

Extracts timecode and duration metadata from GoPro chapter files using ffprobe.

**Primary source:** `timecode` metadata stream (GoPro GPS sync).
**Fallback:** `creation_time` tag in container metadata (typically accurate to ~1s).
**Outputs a warning** if falling back to `creation_time`.

Returns `(timecode_str, source)` where `source` is `"timecode"` or `"creation_time"`.

### `sync_info.json` schema

```json
{
  "cam1_start_timecode": "10:30:00:00",
  "cam2_start_timecode": "10:30:00:05",
  "cam1_detect_offset_s": 0.167,
  "cam2_detect_offset_s": 0.0,
  "offset_s": 0.167,
  "sync_method": "timecode"
}
```

- `offset_s`: `cam2_start − cam1_start` in seconds (positive = cam2 started later)
- `cam1_detect_offset_s` / `cam2_detect_offset_s`: how many seconds into each camera's recording the aligned detection window starts. The earlier camera's offset equals `|offset_s|`; the later camera's offset is 0. Used by `compile_reel.py` to convert detection timestamps back to recording-relative positions.
- `sync_method`: `"timecode"` or `"creation_time"` — indicates reliability

### Concat manifests

`cam1_concat.txt` and `cam2_concat.txt` are standard ffmpeg concat format:

```
ffconcat version 1.0
file '/absolute/path/to/GOPRO1801.MP4'
file '/absolute/path/to/GOPRO1802.MP4'
```

Passed to ffmpeg via `-f concat -safe 0 -i cam1_concat.txt`. No re-encoding.

### Camera alignment for detection

Both cameras record 2-3 minutes of warmup before the game. Their clocks are GPS-synced but may differ by up to ~1s.

After computing `offset_s`, the earlier camera's concat stream is trimmed by `|offset_s|` seconds via ffmpeg `-ss` so both cameras' `t=0` corresponds to the same moment in game time.

Detection timestamps in `events.csv` are relative to this aligned `t=0` (not the raw recording start).

### Signals and detection

`signals.py` is modified to accept either a single MP4 path or an ffmpeg concat manifest path. The concat path is detected by file extension (`.txt`) or an explicit flag. Logic inside `_ffmpeg_gray_frames()` adds `-f concat -safe 0` to the ffmpeg command when a manifest is passed.

`detect_events.py` is otherwise unchanged. The ROI picker receives the first chapter of each camera as its source file for interactive selection.

### `run_detect.sh` — updated folder mode

When invoked as `hockeydetect game_folder`:

1. Calls `discover.py` to find chapters
2. Calls `gopro_meta.py` to extract timecodes → writes `sync_info.json`
3. Builds `cam1_concat.txt` + `cam2_concat.txt`
4. Runs ROI picker if `rois.json` is missing (passes first chapter per camera)
5. Runs `detect_events.py` with concat manifests as cam1/cam2 inputs
6. Runs `timeline_convert.py` and `edl.py` as today

File mode is unchanged.

## Stage 2 — Resolve assembly

### New script: `v3/resolve_scripts/compile_reel.py`

Runs inside Resolve via **Workspace → Scripts**. Requires the template project to be open with the target timeline active.

#### Steps

1. **Pick game folder** via `fusion.RequestDir()` (same pattern as `import_markers_resolve.py`)
2. **Validate inputs:** confirm `events.csv` and `sync_info.json` exist
3. **Import chapters:** import all files from `cam1/` and `cam2/` into a new media pool bin named `"Game Footage — <folder name>"`
4. **Create multicam clip:** use `MediaPool.CreateMultiCamClip()` with timecode sync from `sync_info.json`. Angle 1 = cam1, Angle 2 = cam2.
5. **Read events.csv:** parse all events, apply `cam1_detect_offset_s` / `cam2_detect_offset_s` to convert each event's `start_s` / `end_s` to recording-relative frame positions
6. **Sort events** by `start_s` (chronological game order)
7. **Find stinger end:** read existing clips on Video Track 1, take the last clip's end frame as the placement cursor
8. **Place clips:** for each event, append a multicam clip segment to Track 1 (video + audio) at the current cursor position:
   - Source in: `recording_start_frame + event.start_s × fps − preroll_frames`
   - Source out: `recording_start_frame + event.end_s × fps + postroll_frames`
   - Pre-roll: 3s. Post-roll: 2s. Both clamped to clip boundaries.
   - Angle: set to `primary_cam` from events.csv (1 or 2)
   - Cursor advances by placed clip duration after each event
9. **Log results** to Resolve console: events placed, total reel duration, any skipped events

#### Track placement

- Video Track 1 labeled "Game" — clips placed here
- Audio Track 1 labeled "Game" — audio placed here simultaneously
- Tracks 2–10 (video) and Track 2 (audio) are untouched

#### Event inclusion

All events from events.csv are included in chronological order (Red, Orange, Yellow, Blue). No budget cap — the user trims the reel down to 5-6 min manually. This is intentional: V2 precision (~60%) means pre-cutting to 5-6 min would discard too many genuine highlights.

#### Clip durations

The full detected window is placed for each event (up to V2's `max_win_s` / `max_big_win_s` caps), plus pre-roll/post-roll headroom. The user trims clips in Resolve during review.

## Clip priority reference (Phase 1 approximation)

V2 scores map to colors which approximate event quality. In Phase 1, this is used only for logging/notes — all events are included regardless of color.

| Color | Approximate type | V2 score range |
|---|---|---|
| Red | Goal or sustained high action | > 1.60 |
| Orange | Strong play / likely penalty area | > 1.30 |
| Yellow | Decent play | > 1.00 |
| Blue | Minor play / filler | ≤ 1.00 |

In Phase 2 (ML re-ranker), these approximations are replaced with a trained classifier that distinguishes goals, penalties, and non-scoring plays — enabling proper priority ordering and more accurate budget targeting.

---

## Out of scope (Phase 2 — separate spec)

- **ML re-ranker:** `sklearn.LogisticRegression` trained on labeled V2 feature vectors to classify events as goal / penalty / non-scoring / false positive. Enables: always include all goals, include penalties if budget allows, fill remaining time with non-scoring.
- **VLM keyframe scoring:** moondream2 via ollama (excluded until after Phase 2 is proven)
- **Goal detection automation:** auto-detecting goals from optical flow or audio patterns
- **Slo-mo replay insertion:** automatically duplicating goal clips at reduced speed on a separate track
